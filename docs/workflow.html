Preflight Agent — Phase-by-Phase

Phase 1

Validate Onboarding Answers

Read and validate intake-sources.md against the schema

What It Does

  • Reads intake-sources.md
  • Validates against schemas/onboarding_answers_schema.md
  • Checks: company name, LLM provider, PM system, SCM, default branch, guardrails
  • Asks clarifying questions for missing/ambiguous required fields

Scripts

  • None (agent logic only)

Checkpoint

  • Saves state after completion
Phase 2

Collect Repository List

Ask the customer for all repositories in scope, validate names

What It Does

  • Prompts user for repo list (one per line or JSON array)
  • Validates repo names (alphanumeric, hyphens, no duplicates)
  • Confirms list with user before proceeding

Scripts

  • None
Phase 3

Clone Repositories

Generate SCM connector and clone all repos using scm-bootstrap.py

What It Does

  • Generates SCM connector SKILL.md from SC-SCM contract
  • Clones repos to .sdlc-preflight/repos/
  • Handles failures per-repo: retry, skip, or alternative URL
  • All repos failing = blocking error, pauses workflow

Scripts

  • python3 scripts/scm-bootstrap.py --repos '[...]' --scm github --org <org> --target-dir .sdlc-preflight/repos
Phase 4

Smart Code Scan

Scan each repo for structure, deps, patterns. Parallel for 3+ repos via sub-agents

What It Does

  • Scans each cloned repo for: file structure, dependencies, build tools, linters, test frameworks, patterns
  • Smart filtering: ignores node_modules, dist, binary files, lock files, etc.
  • Tags files as: source, test, config, docs, ci_cd, schema, style, infra
  • Raises clarification questions for ambiguous patterns (e.g., Jest + Vitest both found)
  • Parallel scanning via sub-agents for 3+ repos

Scripts

  • python3 scripts/repo-scanner.py --repo-path .sdlc-preflight/repos/<repo> --output-dir .sdlc-preflight/scans --format both --max-depth 6
Phase 5

Generate Instruction Files

Create .github/instructions/<repo>.instructions.md per repo

What It Does

  • Generates instruction files with: YAML frontmatter, repo structure, deps, tools, patterns, CI/CD, conventions
  • Each file scoped via applyTo pattern to its repo
  • Includes custom instructions placeholder for customer

Scripts

  • python3 scripts/instructions-generator.py --scan-dir .sdlc-preflight/scans --output-dir .github/instructions
Phase 6

Generate Setup Script & Connectors

Create setup.sh, connector skills, observability stack

What It Does

  • Generates setup.sh with: ticket connector, SCM connector, design connector, observability, preflight checks
  • Generates SKILL.md for each connector (from contracts SC-TICKET, SC-SCM, SC-DESIGN, SC-TEST)
  • Optionally installs OTel Collector + Prometheus binaries

Scripts

  • scripts/install-observability.sh (optional)
Phase 7

Generate hooks.json

Register all hooks: guard, secrets, lint, observability, telemetry, learnings

Hooks Registered

  • Guard destructive commands (HC-GUARD-CMD) — always
  • Guard secrets (HC-GUARD-SEC) — always
  • Lint on save (HC-LINT) — if linter detected
  • Observability lifecycle (HC-OBSERVABILITY) — if enabled
  • OTel telemetry (HC-OTEL-TELEMETRY) — if enabled
  • Session learnings (HC-LEARN) — optional
Phase 8

Outcome Inspection & Report

Self-validate all outputs, write preflight_report.md

What It Checks

  • Structural completeness — all required files exist
  • Content quality — no empty/placeholder-only files
  • Consistency — instruction files match scan results
  • Security — no credentials in generated files
  • Functionality — setup.sh has shebang, hooks.json is valid JSON

Scripts

  • python3 scripts/outcome-inspector.py --type preflight --output-dir . --format markdown
  • python3 scripts/outcome-inspector.py --type instructions --instructions-dir .github/instructions --format markdown

Pipeline Generator — Phase-by-Phase

Phase 1

Load Context

Read all contracts, customer onboarding answers, and preflight outputs

Reads

  • All agent contracts: contracts/agent*.contract.md, contracts/orchestrator.contract.md
  • All hook contracts: contracts/hooks/hook_*.contract.md
  • All skill contracts: contracts/skills/skill_*.contract.md
  • intake-sources.md
  • .github/sdlc-pipeline/codebase_scan_results.md (from Preflight)
  • .github/sdlc-pipeline/preflight_report.md (from Preflight)
  • .github/instructions/*.instructions.md (from Preflight)
Phase 2

Ask Clarification Questions

CI/CD, code standards, testing strategy, security, design systems, observability

Topics Covered

  • Tools & Automation — CI/CD, deployment, custom CLIs
  • Ways of Working — PR reviews, approvals, branching strategy
  • Code Standards — architecture patterns, import ordering
  • Testing Strategy — E2E, integration, coverage thresholds
  • Security — scanning tools (Snyk, SonarQube), SAST/DAST
  • Design & UI — design system, component library, Storybook
  • Documentation — ADRs, Swagger/OpenAPI, changelog
  • Observability — APM, structured logging
Phase 3

Resolve Model Mapping

Map contract model tiers to customer's approved LLM models

Tier Mapping

  • reasoning → Best available model (analysis, design, review)
  • coding → Code-optimized model (building, scaffolding)
  • fast → Lowest-latency model (quick checks, lint)
Phase 4

Generate Agent Definitions

Create .md files for each pipeline agent. Parallel groups: A (analysis), B (impl), C (verify)

Parallel Groups

  • Group A: Agent 0, 1, 2, 2a (analysis/design)
  • Group B: Agent 3a, 3b, 3c (implementation)
  • Group C: Agent 4, 5, 6 (verification)
  • Sequential: Orchestrator (depends on all above)

Generation Rules

  • Prime Directive copied verbatim from contract
  • Customer's behavioral guardrails injected into every agent
  • Tool references adapted to customer's stack
  • Custom client context loading instruction included
Phase 5

Generate Skills

Create SKILL.md files for ticket, SCM, design, and testing connectors

Skills Generated (parallel)

  • Ticket Connector — from SC-TICKET (Jira/Linear/ADO/GitHub Issues)
  • SCM Connector — from SC-SCM (GitHub/GitLab/Bitbucket/ADO)
  • Design Connector — from SC-DESIGN (Figma, if applicable)
  • Testing Skill — from SC-TEST
Phase 6

Generate Hooks

Create hook scripts and hooks.json from hook contracts

Hooks Generated (parallel)

  • Guard Destructive — protected paths/branches from onboarding
  • Guard Secrets — protected file patterns
  • Lint on Save — detected linter command
  • Observability Lifecycle — if observability enabled
  • OTel Telemetry — if observability enabled
  • Session Learnings — memory storage path
Phase 7

Custom Client Context Templates

Create empty <agent>_custom_client_context.md for each agent

Template Sections

  • Domain-Specific Rules
  • Additional Constraints
  • Patterns & Preferences
  • Examples
Phase 8

Generate Support Files

Workflow README, repository index template

Outputs

  • .github/agents/agents-workflow/readme.md
  • index.md — repo routing table
Phase 9

Outcome Inspection & Validation

Validate all generated agents against their contracts

Checks

  • Every agent has a corresponding contract
  • Every contract Key Outcome is addressable
  • hooks.json references valid script paths
  • Skill SKILL.md files reference correct CLIs
  • Custom context templates exist for all agents
  • Prime Directives match contracts verbatim

Scripts

  • python3 scripts/outcome-inspector.py --type generator --output-dir . --contracts-dir contracts --format markdown

Scripts Reference

Python repo-scanner.py

Smart repository scanner — analyzes structure, dependencies, build tools, linters, test frameworks, patterns, and conventions.

python3 scripts/repo-scanner.py \
--repo-path .sdlc-preflight/repos/<repo> \
--output-dir .sdlc-preflight/scans \
--format both --max-depth 6
Used by: Preflight Phase 4

Python scm-bootstrap.py

Clones customer repositories. Supports GitHub, GitLab, Bitbucket, Azure DevOps. Shallow clone, retry logic, branch targeting.

python3 scripts/scm-bootstrap.py \
--repos '["repo1","repo2"]' \
--scm github --org <org> \
--target-dir .sdlc-preflight/repos
Used by: Preflight Phase 3

Python instructions-generator.py

Generates .github/instructions/<repo>.instructions.md files from scan JSON. Includes YAML frontmatter, structure, deps, tools, patterns.

python3 scripts/instructions-generator.py \
--scan-dir .sdlc-preflight/scans \
--output-dir .github/instructions
Used by: Preflight Phase 5

Python checkpoint-manager.py

Manages pipeline state — save, load, reset, feedback, error tracking. Enables pause/resume/re-run workflows.

python3 scripts/checkpoint-manager.py save \
--agent preflight \
--phase "Phase 4: Code Scan" \
--status completed \
--state-file .github/sdlc-pipeline/checkpoint_state.json
Used by: All PhasesBoth Agents

Python outcome-inspector.py

Self-validates agent outputs — structural completeness, content quality, consistency, security, functionality.

python3 scripts/outcome-inspector.py \
--type preflight \
--output-dir . \
--format markdown
Used by: Preflight Phase 8Generator Phase 9

Bash install-observability.sh

Downloads OTel Collector + Prometheus binaries. No sudo/Docker required. Auto-detects macOS/Linux, arm64/amd64.

scripts/install-observability.sh # install
scripts/install-observability.sh --check # verify
scripts/install-observability.sh --json # status JSON
Used by: Preflight Phase 6HC-OBSERVABILITY hook
